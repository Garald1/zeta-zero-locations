# PLAN: kernel-checked locations of the zeros of ζ with 0 < Im s ≤ 1000 and ≤ 10 000

Owner: Harald Helfgott (GitHub `Garald1`). Written 2026-11-06 at the end of a sandbox session
that could not build Mathlib (no binary cache, 2 cores). Everything below marked "verified" was
read in the cloned repositories or measured; everything marked "check" is a recommendation or a
name not yet confirmed against the pinned Mathlib.

## 0. Goal and acceptance criteria

Prove the theorems of `challenge/Challenge1000.lean` and `challenge/Challenge10000.lean` (drafts,
generated by `scripts/gen_challenge.py`), so that leanprover/comparator accepts them with
`challenge/comparator-1000.json` and `challenge/comparator-10000.json`. For T = 1000 (n = 649)
and T = 10 000 (n = 10 142):

* `zeros_up_to_T_located`: every zero `s` of Mathlib's `riemannZeta` with `0 < Im s ≤ T` has
  `Re s = 1/2`, `analyticOrderAt riemannZeta s = 1`, and `|Im s − m/10²⁴| ≤ 10⁻²⁰` for some `m`
  in the list;
* `zeros_up_to_T_unique`: each listed interval contains the ordinate of exactly one zero;
* `zeros_up_to_T_count`: `(zerosUpTo T).ncard = n`.

Rules: kernel-checked; axioms only `propext`, `Classical.choice`, `Quot.sound`; no `sorry`,
`native_decide`, `Lean.ofReduceBool`, `implemented_by`/`extern` tricks or new axioms; no
conditional inputs (no RH- or qRH-type hypothesis, no external computation as a hypothesis).
Arb/mpmath only propose data (centres, derivative values, parameters); every inequality the proof
uses is re-derived in the kernel. Finish T = 1000 completely (M0–M3) before scaling to 10⁴ (M4).

## 1. Mathematical architecture

Notation: γ_k listed ordinates, c_k = 1/2 + iγ_k, r = 10⁻²⁰. A certificate may use a finer
centre (the 40-digit Arb midpoints in `data/`) and a smaller radius, as long as each certified
disk lies inside the challenge interval.

### 1.1 Per-zero certificate: one zero on the critical line within r of γ_k

For each k pick a ∈ ℚ(i) (≈ ζ'(c_k)) and κ ≤ 1/2 and prove

* (B1) |ζ'(z) − a| ≤ κ|a| for all z in the closed disk D = D̄(c_k, r);
* (B2) |ζ(c_k)| ≤ (1 − κ)|a| r.

Then g(z) = z − ζ(z)/a maps D into D and is κ-Lipschitz on D (mean value inequality on the
convex set D), so by the Banach fixed point theorem (Mathlib's `ContractingWith`, applied on the
complete subtype D; check the exact API) ζ has exactly one zero ρ_k in D, and ζ'(ρ_k) ≠ 0.

On the line: s ↦ 1 − s̄ sends zeros of ζ (off the real axis) to zeros, by `riemannZeta_one_sub`
and `riemannZeta_conj` (both used in the reused repos, so present in their Mathlib), and maps D
onto itself, since |1 − s̄ − c_k| = |s − c_k| when Re c_k = 1/2. By uniqueness ρ_k = 1 − ρ̄_k,
so Re ρ_k = 1/2: ζ(1/2 + i t_k) = 0 with |t_k − γ_k| ≤ r.

Getting (B1) and (B2) from a computation:

* Let F = F_{N,K} be the Euler–Maclaurin main part and E = E_{N,K} its explicit error bound from
  `riemannZeta_EM_real` (rh-up-to-15-lean, `ZetaZeros/EM2.lean`, verified statement):
  ‖ζ(s) − (Σ_{n ∈ range (N+1)} 1/n^s + N^{1−s}/(s−1) − N^{−s}/2 + Σ_{i ∈ range (k+1)} emTerm N s (2i))‖
  ≤ (Π_{i<2k+2}(|Re s + i| + |Im s|)) / (2k+2)! · |B_{2k+2}| · exp((−(Re s + 2k+2) + 1) log N) / (Re s + 2k+2 − 1),
  valid for Re s > 0, s ≠ 1, N > 0.
* (B2): |ζ(c)| ≤ (kernel upper bound for |F(c)|) + E(c).
* (B1): |ζ'(z) − a| ≤ |F'(c) − a| + |(ζ − F)'(c)| + r · sup_{w∈D} |ζ''(w)|, where
  - |(ζ − F)'(c)| ≤ sup_{|z−c|=ρ₀} E(z)/ρ₀ by the Cauchy estimate
    (`Complex.norm_deriv_le_of_forall_mem_sphere_norm_le`, used in the reused repos), ρ₀ = 1/4;
  - sup_D |ζ''| ≤ M/(ρ₁ρ₂) by two Cauchy estimates, M any crude bound for |ζ| on a disk of
    radius about 1/4 around c (since r = 10⁻²⁰, even M ≤ 10¹⁵ is enough; e.g. from
    `zeta_eq_order1` in EM2.lean);
  - F'(c) is computed in the kernel together with F(c) (accumulate −log n · n^{−s}; differentiate
    the EM terms).

Numbers (Arb, not rigorous, `scripts/scan_above_1e4_and_stats.py`): min |ζ'(ρ)| ≈ 0.79 over the 649 zeros up to
1000 and ≈ 0.40 over the 10 142 zeros up to 10⁴; minimal gap between consecutive ordinates 0.31
(up to 1000) and 0.0377 (up to 10⁴: the Lehmer pair near 7005.1). So (B2) needs |ζ(c)| ≲ 10⁻²¹;
the evaluator of §2 reaches about 10⁻²⁶.

* T = 10⁴: no T₂ in [10⁴, 10000.0653) has a positive leg (best minimum ≈ −0.012). In the next

* (C1) Re ζ > 0 on [1/2, 2] + iT₂: evaluate ζ(σ_j + iT₂) at sample points with the same

  cheap.
* (C2) An enclosure of arg ζ(1/2 + iT₂) from the computed value (Re > 0). Pattern: zeta-lab

* (C4) Ncount 100 T₂ ∈ (n₂ − 30, n₂ − 28), with n₂ = 649 resp. 10 143; hence it equals n₂ − 29.

## 2. The kernel evaluator

### 2.1 What the prototype established (`prototype/`, Lean 4 core only, Lean v4.36.0-rc2)

* `decide +kernel` on Nat-only functions; the kernel's GMP-accelerated `Nat` operations cost
  roughly 4 µs each in this style.
* Style matters. The first version (`prototype/old/ZetaEval.lean`: Int balls in structures with
  typeclass operators) took about 5 s per point at N = 350, against about 0.25 s for
  `ZetaEval2.lean`. In `prototype/micro/`, a forced Int loop was about 2× slower than the same Nat
  loop, and unforced Int/structure loops of 10⁴ steps hit `(kernel) deep recursion detected`. Force
  every step by matching on a `Nat` (see `ZetaEval2.go`).
* `prototype/ZetaEval2.lean`: offset-binary fixed point (value x stored as x·2^96 + 2^128),
  p^{−s} for primes by reduction mod 2π (uncertified constant), Taylor and 7 squarings, composite n
  by complete multiplicativity (depth-first enumeration of non-decreasing prime products),
  accumulating S = Σ_{n≤N} n^{−s} and S' = −Σ log n · n^{−s} at s = 1/2 + it. Measured with
  `decide +kernel`, whole file including Lean start-up:
  - t ≈ 999.79, N = 350 (70 primes): 0.46–0.47 s;
  - t ≈ 9998.85, N = 3500 (489 primes): 2.9–3.1 s (two runs; `prototype/run_bench.sh`);
  - a deliberately wrong expected value is rejected (`B2_1000_bad.lean`).
* Extrapolated: about 3 min of kernel time for the 649 zeros up to 1000, about 4–5 CPU-hours for
  the 10 142 zeros up to 10⁴ (before EM terms and error-radius bookkeeping).

### 2.2 Design for the real evaluator (with its soundness proof in mind)

* Ball arithmetic on `Nat`: fixed-point midpoint plus a `Nat` radius in ulps; one containment
  lemma per primitive (add, sub, mul, shift, complex mul), proved once over ℝ/ℂ, so the soundness
  of every composite routine follows structurally. Template: zeta-lab `lean/ZetaLean/Rigor.lean`
  (exact ℚ intervals with containment lemmas; too slow for the bulk sums, but the right pattern).
* Precision P = 128 bits (costs about the same as 96).
* log p for primes p ≤ N: certify ℓ_p with |log p − ℓ_p| ≤ 2^−138 once (not per zero), e.g. by
  checking exp-bounds in the kernel (`Real.exp_bound`, `Real.exp_bound'`), or via zeta-lab
  `lean/ZetaLean/IntervalExp.lean` (`Interval.log1`, `Interval.log2I`; exact ℚ, fine for a few
  hundred constants).
* p^{−1/2}: certify w_p by integer checks w_p² · p ≤ 2^{2P} ≤ (w_p + 1)² · p.
* e^{−ix} without π: Taylor sum (`Complex.exp_bound`) at x/2^k with k ≈ 24, then k squarings.
  This avoids reducing mod 2π, which would need π to about 45 digits, while Mathlib's
  `Real.pi_gt_d20` / `Real.pi_lt_d20` give 20. The extra squarings cost roughly 15%. A certified π
  (Machin) would be an optional optimisation. zeta-lab `lean/ZetaLean/IntervalCExp.lean`
  (`ComplexInterval.expC`, `dirichletTerm`) does the same halving/squaring scheme in exact ℚ.
* Composite n: complete multiplicativity (`natCast_mul_natCast_cpow` is used in the reused repos).
  The DFS enumeration is fast; its soundness proof must show every n ≤ N appears exactly once
  (unique factorisation). Simpler-to-prove alternative: iterate n = 1..N with a smallest-prime-
  factor certificate and keep earlier values in a balanced tree keyed by n (O(log N) access; `Array`
  access reduces through `List` in the kernel and is O(n)).
* EM terms: need B_2, …, B_{2k+2} as explicit rationals. Mathlib's `bernoulli'` is defined by
  well-founded recursion, which the kernel will not evaluate efficiently (check); prove the values
  one by one from `bernoulli'_def` with `norm_num`.
* Each check is a `Bool` function on `Nat` data with a soundness theorem
  `check_sound : check d = true → (inequalities)`, used as `check_sound d (by decide +kernel)`.
* About 50 zeros per module, so `lake build` uses all cores.

### 2.3 Parameters (from `scripts/em_params.py`, the formal remainder bound of `riemannZeta_EM_real`)

Smallest k with remainder bound < 10⁻²⁶ at s = 1/2 + it:

| t | N = 0.35 t | N = 0.5 t | N = t |
|---|---|---|---|
| 1000.13 | k = 39 (B up to B₈₀) | k = 26 (B₅₄) | k = 16 (B₃₄) |
| 10000.26 | k = 38 (B₇₈) | k = 26 (B₅₄) | k = 16 (B₃₄) |

Recommended start: N ≈ t/2, k = 26. Cost is dominated by the Dirichlet sum (∝ N).

Rough cost estimate for the real evaluator: 2–3× the prototype per zero (larger N, extra
squarings, radius bookkeeping, S' alongside S), i.e. about 10 min for T = 1000 and about 10–15
CPU-hours for T = 10⁴ (about 1–1.5 h on 12 cores). Comparator replay re-runs the kernel
computations, possibly single-threaded: measure on T = 1000 first.

## 5. Pitfalls already met

* Use `decide +kernel`, not plain `decide` (the elaborator's evaluation is far slower).
* Explicit `Nat.add`, `Nat.mul`, `Nat.sub`, `Nat.div`, `Nat.shiftRight`, `Nat.ble` in hot loops;
  no `Int`, typeclass arithmetic or structures there.
* Force accumulators each step, e.g. `match Nat.add a b with | 0 => … | _ => …`.
* Long data lists: chunk them (≤ 300 entries per `def`), as in `prototype/B2_10000.lean` and the
  challenge files.
* Arb's isolation (`data/*.txt`) is only candidate data: nothing in the proof may rely on it.
